# Kilowatts Authentication Phase

This package contains the modular Flutter `lib/` implementation for the Kilowatts authentication wireframes.

## Implemented

- Welcome / Splash-style entry screen
- Firebase Email/Password sign-in
- Account creation
- Firebase display-name update
- Mandatory email verification gate
- Verification resend with cooldown
- Automatic verification refresh when the app resumes
- Forgot-password flow
- Privacy-preserving password-reset response
- Persistent Firebase native auth session
- Sign-out
- Centralized Firebase error mapping
- Reusable fields, buttons, auth layout and theme
- Responsive max-width layout for phones/tablets
- Validator unit tests

The original OTP reset wireframe was intentionally translated to Firebase's real email verification/reset-link flow. The app does not fabricate an OTP that Firebase did not issue.

## 1. Copy the source

From the generated package, copy `lib/` into:

```bash
~/dev/kilowatts-mobile/lib/
```

Your branding assets already belong at:

```text
assets/branding/
```

The UI expects:

```text
assets/branding/kilowatts_logo_transparent.png
```

## 2. Add FlutterFire

From the Flutter project root:

```bash
flutter pub add firebase_core
flutter pub add firebase_auth
```

Install the Firebase and FlutterFire CLIs if needed:

```bash
npm install -g firebase-tools
dart pub global activate flutterfire_cli
firebase login
```

Then run:

```bash
flutterfire configure
```

Select the Firebase project for Kilowatts and the Android platform. This generates the real:

```text
lib/firebase_options.dart
```

Do not manually invent Firebase API keys/project identifiers in source code.

## 3. Firebase Console

In Firebase Console:

1. Open **Authentication**.
2. Enable **Email/Password** under Sign-in method.
3. Under Authentication settings, configure a password policy in **Require** mode. Recommended baseline matching this UI:
   - minimum length: 8
   - uppercase required
   - lowercase required
   - numeric required
4. Keep/enable email-enumeration protection.
5. Customize the email-verification and password-reset templates with Kilowatts branding before release.

## 4. Assets

Ensure `pubspec.yaml` contains:

```yaml
flutter:

    - assets/branding/
```

## Authentication state flow

```text
Firebase user == null
        ↓
Welcome
        ↓
Login / Create Account
        ↓
Signed in but email not verified
        ↓
Email Verification Gate
        ↓
Verified Firebase user
        ↓
Authentication Complete
```

The `AuthenticationCompleteScreen` is the deliberate hand-off point for the next Kilowatts phase. It should later be replaced by the first-time system setup / MQTT connection gate without changing authentication internals.

## Security decisions

- No password is stored by Kilowatts code.
- No raw Firebase error messages are shown to users.
- Login uses a generic invalid-credentials message.
- Password reset does not disclose whether an email is registered.
- Unverified accounts cannot enter the authenticated application path.
- The native Firebase session is used instead of implementing an unreliable custom "Remember me" mechanism.
- Password reset uses Firebase's real reset-email mechanism rather than a fake in-app OTP.

## Files intentionally not included

`firebase_options.dart` is not included because it is project-specific and must be generated by `flutterfire configure` for the actual Firebase project.
